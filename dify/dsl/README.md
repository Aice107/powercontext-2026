# DSL 说明

## 文件

| 文件 | 用途 | 导入顺序 |
| --- | --- | --- |
| `01_inn_chatflow.yml` | 主应用《记仇客栈》，advanced-chat 模式 | 1（唯一必需） |

本作品只有一个应用，无需按顺序导入多个 DSL。

## 版本

- 导出方：Dify **1.17.0**（DSL `version: 0.7.0`）
- 已验证：同一文件重新导入 1.17.0 返回 `status=completed`（无 warning）
- 依赖插件：`langgenius/openai_api_compatible:0.0.73`（Marketplace），已写入 `dependencies`，缺失时导入会提示安装

## 导入后必须重绑定的三处

1. **三个 HTTP 节点**（读取档案 / 记账 / 结算）：`url` 里的 `http://127.0.0.1:8010` 换成实际 inn-api 地址；
   若 Dify 跑在容器里，`127.0.0.1` 指向容器自身，应改为宿主地址或 `host.docker.internal`。
2. **六个模型节点**（判定意图 / 三娘回应 / 闲聊回应 / 逐客令 / 写账本长卷）：选择你自己配置好的模型；
   要求模型支持 **function calling**（「判定意图」用参数提取器）。
3. **无需重绑知识库**：本作品不使用知识库。

## 节点结构（19 个节点）

```
start → 读取档案 → 后端是否可用 ─┬─(否)→ 兜底回答
                                └─(是)→ 判定意图 → 是否打烊 ─┬─(是)→ 结算 → 写账本长卷 → 回答
                                                            └─(否)→ 是否闲聊 ─┬─(是)→ 闲聊回应 → 回答
                                                                              └─(否)→ 记账 → 生成传闻 → 是否逐客 ─┬─(是)→ 逐客令 → 回答
                                                                                                    └─(否)→ 三娘回应 → 回答
```

分支处的判断依据：

| 节点 | 条件 | 依据 |
| --- | --- | --- |
| 后端是否可用 | `status_code ≥ 400` | HTTP 节点异常时走 `default-value`（500），保证不崩 |
| 是否打烊 | `intent is closing` | 参数提取器结果 |
| 是否闲聊 | `intent is chat` | 参数提取器结果 |
| 是否逐客 | `body contains "TIER=4"` | 记账接口返回的上下文块（仇值触顶） |

> 「生成传闻」节点对每个事件都调用，但后端只接受 `severity ≥ 4` 的事件，低严重度返回 `created=false`，避免传闻表被灌水。
