解决什么问题

找笔记难

"我明明记过 ef_search 怎么调"——课题组文档散落，Ctrl+F 找不回；纯向量检索对参数名、错误码这类硬信号又很迟钝。 格物用 seekdb 的混合检索把两条路放进一条 SQL：语义负责"大概在讲同一件事"，全文负责"必须出现的硬信号"，融合排序在数据库内部完成。

写汇报烦

每周组会材料是重复劳动，导师的偏好（结论先行、必挂出处、提前一天发）每次都靠人肉遵守。 格物把这些偏好写进 PowerContext 记忆，生成草稿时真实生效——并且你能看到"哪条记忆改变了输出的哪一段"。

核心功能

① 导入即索引

粘贴或批量导入 markdown：front matter 解析出课题/类型/日期，按小节分块，本地 ONNX 向量化后写入 seekdb 堆表（向量列 + ngram 全文索引 + 标量列）。16 篇示例语料 → 56 分块，全程约 5 秒。

② 混合检索带出处

hybrid / vector / fts 三种模式可对照；课题、类型、日期窗口作为 filter 下推到两路检索；结果逐条带《标题 · 小节 · 日期》出处；界面可展开"查看 seekdb 取证"看到实际执行的 SQL。

③ 记忆跨会话复用

偏好写入 PowerContext 后，即使重启服务、换个会话召回，仍按语义命中（matched_by 含 vector）。记忆读写全程 JSONL 留痕，可核对。

④ 组会草稿 + 证据链

确定性装配：记忆决定版式（结论先行/先给数据/挂出处/提前一天提醒），检索提供事实与数据。附录列出命中的记忆条目、seekdb SQL 与"本次因记忆改变的输出"清单。

技术实现

浏览器 ──► 格物主应用 (FastAPI :8712)
             ├─ seekdb（嵌入式 pylibseekdb，一份实例两个使用方）
             │    ├─ 知识层：堆表 chunks（向量 + ngram 全文 + 标量列）
             │    └─ dbms_hybrid_search.search(...)：向量+全文+过滤+RRF 一条语句
             ├─ PowerContext Server (:8000，DATABASE_KIND=seekdb)
             │    └─ 记忆层：atomic-memory 写入 / hybrid 召回 / 生命周期
             └─ 本地向量服务 (:8710) ─ ONNX Runtime CPU，零云端 Key
  • 一个 seekdb、两个使用方：PowerContext 的记忆表（database test）与应用的知识表（database gewu）共享同一嵌入式实例；
  • 实测确定的工程细节：混合检索仅支持堆表；range 只接受数值常量 → 日期用 int（yyyymmdd）；向量单位归一化后 l2 序等价余弦序；
  • 确定性草稿：同样输入逐字节一致输出，评审可复现、可核对记忆的真实作用；
  • 无参数绑定下的注入防护：自建 SQL 字面量转义层，配套单元测试（5 passed）。
